How it works

Built around the subscriptions you already have

Pick yours. Relay reads what's left, works out what will expire, and burns the most-likely-wasted first, while keeping a reserve for your day.

Rolling 5-hour windows

Windows reset whether you used them or not. Relay counts every window that falls inside your downtime, then fills it.

  • Downtime from your hours: weeknights 23:00–07:00, weekends all day
  • Weekly reset tracked so it never drains your Monday
  • A reserve is kept for your own daytime use (30% by default)
$ relay burn capacity -b burner.json
downtime window: Wed 23:00 → Thu 07:00
claude-max  21 windows left · resets Mon 09:00
            13 × 5h windows fall in your idle time
            tonight: 1 window

Agent37 instance budget

Read live from the Agent37 budget API. The shift runs on an always-on Agent37 instance, woken by an Agent37 platform cron at 23:00.

  • GET /v1/instances/{id}/budget: monthly remaining + credit
  • 402 instance_budget_exhausted → instant switch to the next provider
  • The LLM router gives you the whole OpenRouter catalog as a cheap tier

Metered API budgets

OpenAI, OpenRouter, anything OpenAI-compatible. Spend comes from Relay's own ledger, and tonight's allowance is capped so a long night never blows the month.

  • Per-subscription allowance, split across the nights left before the reset
  • Per-model and per-project soft caps
  • Every call priced at API list rates into .relay/events.jsonl

Your plan, in markdown

Projects, a repo, a test gate, a budget and checkboxes. Relay works top to bottom, commits each task that passes the gate, and writes the result back.

  • [x] done with the commit sha, [!] blocked with exactly what it needs
  • A draft PR per project on relay/night-<date>
  • BLOCKED: instead of guessing at credentials or product calls
## greet-cli
repo: github.com/you/greet
test: python3 greet.py | grep Hello
budget: 1.50

- [x] add a --name flag (relay 7cddf23)
- [!] publish to PyPI (blocked: needs a token)

Integrate

Plug it into the harness you already use

Four ways in, from zero code to full control. All of them write the same ledger, so relay savings counts everything.

ZERO CODE · OPENAI-COMPATIBLE

relay serve

Point any harness's base URL at Relay: OpenCode, Hermes, Aider, LangChain, your own scripts. You get model failover on 429/402/quota/context, burn-order routing, and every call priced into your savings.

$ relay serve -c burner.json        # http://127.0.0.1:8037/v1
export OPENAI_BASE_URL=http://127.0.0.1:8037/v1
export OPENAI_API_KEY=$RELAY_SERVE_KEY
# model: "relay/auto" lets Relay pick
AGENTS · MCP

relay mcp

Give Claude Code, Hermes or OpenCode tools to check capacity, read savings, and queue work for tonight. An agent can say "add this to tonight's shift."

$ claude mcp add relay -- python3 -m relay.mcp
tools: relay_capacity · relay_savings
       relay_plan_list · relay_plan_add
       relay_burn  (opt-in: RELAY_MCP_ALLOW_BURN=1)
HOSTED · AGENT37

An always-on instance with the Agent37 LLM router built in, woken nightly by a platform cron that fires even while the box sleeps. Your laptop can stay closed.

Build your own

Zero dependencies, stdlib only. Use the router, the unstick ladder, the capacity planner or the savings ledger directly in your own harness.

from relay.config import load, build_router
from relay import capacity, value
router = build_router(load("burner.json"))
spec, switch = router.pick()   # fails over for you
print(value.render(value.month()))

The engine

Nobody's awake. It can't get stuck.

It fails over the moment a model hits a limit. When the agent loops, hangs or goes nowhere, it climbs an unstick ladder: a cheap second opinion, then a stronger model, then a clean reset. Once things are moving again, it drops back to the cheap model.

When the agent says no
Unattended agents need a rule for refusals. Relay never shops around for a model that will say yes.

  

    
"kill whatever is running on port 8000…"
 

    
"write a keylogger that emails me passwords"
 

  

  
A refusal only counts as a blocker when an independent reviewer judges the task benign. If the reviewer agrees with the refusal, if the review fails, if no reviewer is available, or if a second model also refuses, the refusal stands and the task goes to "needs you" in the morning report.






  
FAQ
Questions

  

    
Will it push to my main branch?
No. Every task is a commit on relay/night-<date> and each project gets a draft PR. A task only counts as done if the project's test gate passes; otherwise it's marked [!] with the reason.

    
Does my laptop have to stay on?
Not with Agent37. The shift runs on an always-on Agent37 instance, started by an Agent37 platform cron that fires even while the instance sleeps. You can also run it locally with relay burn run --wait.

    
What if the agent gets stuck at 3 a.m.?
Limits (429, 402, quota, context) trigger an immediate switch. Loops, hung processes, dead ends and over-refusals climb the unstick ladder: a hint, then a stronger model, then a reset. Anything that needs a human is written up for the morning.

    
How do I plug in my own harness?
Easiest: run relay serve and set your harness's OpenAI base URL to http://127.0.0.1:8037/v1. For agents with MCP support, claude mcp add relay -- python3 -m relay.mcp. Or import the Python package.

    
Does it use up my whole plan?
No. Each subscription keeps a reserve for your daytime use (30% by default), and tonight's allowance is spread across the idle nights left before the reset.
