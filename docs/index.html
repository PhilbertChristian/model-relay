When your agent gets trapped,
Relay switches the model and gets it moving again.

Agents get stuck all the time. They hit a rate limit or budget wall, retry the same broken command forever, start a process that never exits, or keep digging down the wrong path. Relay watches for all four, then climbs an unstick ladder: a cheap second opinion first, then a stronger model, then a clean reset. It drops back to the cheap model as soon as the agent is moving again, so you only pay for the big model when you actually need it.

Four ways an agent gets trapped

  
Relay detects each one, both in its own agent loop and live on an agent hosted on Agent37.

  

    
limit
Hits a wall
A 429 rate limit, a 402 instance_budget_exhausted or insufficient_quota, a context-window overflow, or a soft $/token cap you set per model. Relay fails over right away: it cools the model down, disables the provider, or moves to a model with a bigger context window.

    
loop
Retries the same thing
The same tool call with the same result 3 times, or 3 tool errors in a row. On a hosted agent, Relay counts identical tool_call.started events live in the stream and cancels the turn.

    
hung
Process never returns
Every shell command runs in its own process group under a watchdog. If it hangs, the whole group is killed. The model is told to background servers, and the event counts as a blocker. On a hosted agent: if nothing but keepalives arrives for N seconds, Relay cancels the turn.

    
wrong approach
Busy, but going nowhere
10 steps without changing a file, or a reply identical to the previous attempt. The agent is active but not making progress.

  


  
The unstick ladder

  
Relay starts with the cheapest fix and only escalates when that doesn't work.

  

    
1Second opinion
The strongest healthy model reads the last few steps and writes a five-bullet diagnosis. The cheap model keeps driving with that hint. It costs one call, not a whole session on the big model.

    
2Swap model
The whole conversation is handed to the next tier with a handoff note. After N clean steps, Relay de-escalates back to the cheap tier.

    
3Kill & reset
The context itself is the problem now. Relay trims it to the task, the lessons learned so far, and the files already changed, then starts a fresh plan on the next model.

  


  
Architecture

  
relay (python, zero dependencies)
 ├─ agent loop        tools: read / write / edit / list / bash (watchdog) / escalate
 ├─ blocker detector  loop · error streak · hung · no-progress · malformed
 ├─ router            tiers · cooldowns · dead providers · context floor · soft caps · de-escalation
 ├─ providers         any OpenAI-compatible API, errors classified → limit kind
 │    ├─ Agent37 LLM router   https://api.agent37.com/llm/v1   (dozens of OpenRouter models, per-instance budget)
 │    └─ OpenAI               https://api.openai.com/v1
 ├─ supervisor        watches a hosted Agent37 agent's SSE stream, cancels trapped turns,
 │                    re-sends on the same session with a different model
 └─ telemetry         .relay/events.jsonl  +  Supabase relay_events (calls, switches, blockers, savings)

Unsticking agents: what works

  
The techniques Relay builds on, and where each one appears in the code.

  

    
TechniqueIdeaIn Relay

    
Model cascadesTry the cheap model first and escalate only when needed. Most steps don't need the frontier model (FrugalGPT; RouteLLM-style routers).Tiered ladder + de-escalation, router.py

    
Provider failoverTreat 429, 402 and quota errors as routing signals, not fatal errors. Cool the model down, honour Retry-After, and disable an exhausted provider.providers.classify, Router.record_error

    
Loop / repetition detectionHash each (action, args, result). Seeing the same hash N times means the agent isn't learning from its own feedback.blockers.py, supervise.Watch

    
WatchdogsEvery external action gets a deadline. Kill the whole process group, not just the shell, and say why.Toolbox.t_bash

    
Critic / reflectionA second model critiques the trajectory, and its verbal feedback is fed back in (Reflexion, self-critique). Cheaper than switching drivers.Rung 1 Agent._hint

    
Context reset / compactionA long, error-filled context keeps pulling the model back into the same mistakes. Keep the task and the lessons, drop the rest.Rung 3 Agent._reset, _compact

    
Escalate as a toolLet the model raise its hand. A self-reported blocker is the cheapest signal you can get.escalate tool

    
Budgets as guardrailsPer-model $/token caps retire a model before it drains the wallet. Per-instance budgets on Agent37 are a second line of defence.max_usd / max_tokens

  


  
Run it


# offline demo: no keys needed
git clone https://github.com/PhilbertChristian/model-relay && cd model-relay
python3 -m relay -c examples/demo-mock.json -C /tmp/demo -y run "create hello_relay.py and run it"

# real models: OpenAI locally, or the full ladder on Agent37
export OPENAI_API_KEY=sk-...  AGENT37_API_KEY=sk_live_...
python3 deploy/agent37.py create --budget 2     # instance with $2 of managed-LLM headroom
python3 deploy/agent37.py push                  # ship relay + relay.json
python3 deploy/agent37.py run "build a todo CLI with tests"

# supervise an agent already hosted on Agent37 (Hermes, OpenCode, OpenClaw...)
python3 -m relay supervise --instance ab12cd34ef --models default,sonnet,opus "fix the failing build"
